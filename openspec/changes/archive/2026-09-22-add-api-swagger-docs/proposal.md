## Why

The backend's REST API (currently `/api/healthz`, `/api/projects`, `/api/events`) has no interactive, browsable documentation - the only reference is the `backend-api-contract` OpenSpec spec and reading handler source. As more feature changes add endpoints (Kanban, spec authoring, dependencies, AI provider config, specflow), that gap grows. Wiring Swagger/OpenAPI now, while the surface is still small, establishes the annotation convention every future handler follows, instead of retrofitting it later across many handlers at once.

## What Changes

- Add `swaggo/swag` doc-comment annotations to every existing JSON handler (`GET /api/healthz`, `GET /api/projects`, `POST /api/projects`), describing method, path, request body, response shape, and status codes.
- Document `GET /api/events` for discoverability (path, description that it is an SSE stream) without a JSON response schema, since swag's schema annotations don't fit a streaming endpoint.
- Add a `swag init` generation step (Makefile target) that produces the OpenAPI spec into `backend/docs/`.
- Wire `gin-swagger` into the router to serve the generated spec's interactive UI at `/swagger/*any`, mounted alongside the existing `/api` group.
- Establish the convention (documented in `project.md`) that every new handler added by a future change carries swag annotations from the start - not new scope for this change, just a project-level convention update.

## Capabilities

### New Capabilities
- `api-docs`: Generating an OpenAPI spec from Gin handler annotations via swag, and serving it as an interactive Swagger UI.

### Modified Capabilities
- None. `backend-api-contract` (from `add-studio-foundation`) already covers the REST/SSE contract's shape and is not being changed - this change adds a documentation surface on top of it, not new request/response behavior.

## Impact

- New directory: `backend/docs/` (generated by `swag init`; not hand-edited).
- New dependencies: `github.com/swaggo/swag` (CLI + annotations), `github.com/swaggo/gin-swagger`, `github.com/swaggo/files`.
- New Makefile target (`make swagger` or folded into `make build`) to regenerate docs.
- Existing handler files (`healthz.go`, `projects.go`, `events.go`) gain doc comments; no behavioral changes to any endpoint.
- `project.md` gains a documented convention: new handlers carry swag annotations.
